# 01 — Extraction: pulling the desktop app apart

Target: the OpenCode **desktop app** (Electron), which *does* get free-tier
access. We wanted to see what the official client sends to zen.

## 1.1 Binary + app bundle

- OpenCode CLI binary: `~/.opencode/bin/opencode` (v1.18.31) — the real client
  used throughout.
- Desktop app bundle lives wherever Electron installed it. The interesting parts
  are inside `resources/app.asar`.

## 1.2 Extracting app.asar

Node ships a tiny `asar` tool:

```bash
npx asar extract app.asar /tmp/opencode/asar
```

Key files that came out:

| file                    | size  | what it is                              |
|-------------------------|-------|-----------------------------------------|
| `index.js`              | 164KB | Electron main process (window/server glue) |
| `sidecar.js`            | small | spawns the headless server, sets auth env |
| `node-DgabECgI.js`      | 34MB  | the whole opencode server bundled       |

## 1.3 The sidecar — how the desktop runs its own server

`sidecar.js` (read in full) revealed:

```js
OPENCODE_SERVER_USERNAME = "opencode"
OPENCODE_SERVER_PASSWORD = "<generated>"   // via env
XDG_STATE_HOME           = userDataPath    // ~/.config/ai.opencode.desktop
// ensureLoopbackNoProxy, useEnvProxy ...
```

and it starts the exact same server OpenCode runs normally:

```
opencode server listening on http://127.0.0.1:34913
```

So the *desktop == a local `opencode serve`* with Basic auth
(`opencode:<OPENCODE_SERVER_PASSWORD>`).

## 1.4 Live listener confirmed

```
ss -tlnp → 127.0.0.1:34913  pid 2610  (ai.opencode.desktop sidecar)
```

## 1.5 Key insight from extraction

The desktop's requests to zen are generated by the **same bundled opencode
server** you get from `opencode serve`. So if we run our *own*
`opencode serve`, that's a genuine client session — which is exactly what zen's
free-tier gate recognizes. (See `04-the-loophole.md`.)
